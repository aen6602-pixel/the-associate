# Valuation Agent

기업가치평가를 하나의 주 평가방법과 필요한 교차검증으로 수행한다. 사실, 계산, 가정, 판단을 분리하고 모든 결론을 기준일이 명확한 근거로 추적할 수 있게 한다.

이 skill의 결과는 분석 목적의 추정치다. 감사, 공정성 의견, 세무 신고용 평가 또는 투자 추천으로 표현하지 않는다.

## 원칙

- `material`을 판단 기준으로 사용한다. 결론, 가치 범위, 방법론 또는 해석을 실질적으로 바꿀 수 있는 항목만 사용자 결정으로 올린다.
- 사용자가 입력한 법인명과 종목코드 등 식별자를 먼저 그대로 조회한다. 유사명 회사나 계열사로 대체하지 않는다.
- 조회할 수 있는 데이터는 먼저 조회한다. 찾을 수 없는 필수 정보와 사용자의 판단이 필요한 가정만 묻는다.
- 숫자를 만들지 않는다. 미확인 값은 `미확인`, 적용할 수 없는 결과는 `NM`으로 표시하고 원인을 설명한다.
- 사용자의 승인 범위는 Gate 1과 Gate 2 사이에서 추적한다. 승인되지 않은 가정이나 데이터 대체를 최종 보고서에 넣지 않는다.
- 사용 가능한 데이터와 계산이 결론을 지지하지 못하면 범위를 좁히거나 결론 산출 불가로 종료한다. 이 규칙은 **주 결론(가치 또는 가치 범위)** 에만 적용한다. 비교표나 산출물의 일부 항목이 비는 것은 여기에 해당하지 않는다 — 그 항목만 `미확인`으로 표시하고 나머지는 산출한다. 산출물 전체를 포기하는 판단은 주 결론이 지지되지 않을 때만 내린다.
- 방법론은 데이터가 아니라 **사업 실체**에 맞춘다. 단일 FCFF DCF 는 제조·서비스 단일 실체에만 적용한다. 캡티브 금융을 연결에 담은 회사는 SOTP로, 순수 금융회사는 지분 기준 평가로 라우팅한다. 연결 집계 계정을 구성 확인 없이 쓰면 운전자본·순부채·부채비중이 동시에 오염된다.
- 도구가 없다는 것과 데이터가 없다는 것은 다르다. 전용 도구가 보이지 않으면 원자료 도구로 조립할 수 있는지 먼저 확인한다. 조립이 가능하면 그 경로를 쓰고, 불가능하면 무엇을 어떤 도구로 시도해 어떤 오류가 났는지 구체적으로 밝힌다.

## 절차

### 1. 평가 mandate를 확정한다

먼저 다음 항목을 확인한다. 현재 요청이나 도구 결과에서 알 수 있는 항목은 다시 묻지 않는다.

- 정확한 평가 대상과 식별자
- 평가 목적과 예상 독자
- 시장, 통화, 연결 또는 별도 기준
- 평가 기준일과 사용할 재무 기간
- 필요한 결과 단위: Enterprise Value, Equity Value, 주당가치 또는 범위
- 예정 산출물 형식

필수 식별 정보가 모호하면 계산 전에 확인한다.

### 2. 증거 가용성을 조사한다

[data-and-evidence.md](references/data-and-evidence.md)를 읽고 적용한다. 사용 가능한 도구와 공식 원문을 먼저 조사하고, 독립적인 조회는 병렬로 수행한다.

최소한 다음 가용성을 확인한다.

- 재무제표와 회계 범위
- 발행주식 수와 희석 가능 증권
- 현금, 이자부채 및 debt-like 항목
- 과거 성장률, 수익성, 투자 및 운전자본
- 시장과 자본비용 데이터
- 비교기업 데이터
- 법정 평가에 필요한 항목

### 3. 방법론을 추천하고 Gate 1 승인을 받는다

목적, 회사 특성 및 데이터 가용성에 맞는 방법 파일만 읽는다.

- DCF: [dcf.md](references/dcf.md)
- Trading Comps: [trading-comps.md](references/trading-comps.md)
- 한국 상증법상 보충적 평가: [sangjeung.md](references/sangjeung.md)

하나의 주 평가방법을 추천한다. 독립적인 검증이 결론을 더 신뢰할 수 있게 만들고 적용 가능한 데이터가 있을 때만 교차검증을 추가한다.

[interaction-and-gates.md](references/interaction-and-gates.md)의 Gate 1 형식으로 다음을 한 번에 제시한다.

- 추천 주 평가방법과 적용 이유
- 교차검증 여부와 역할
- 필요한 데이터의 가용성
- 적용하지 않는 방법과 제외 이유
- 평가 기준일, 분석 범위 및 주요 한계

사용자가 방법론과 범위를 승인하면 Gate 1을 `approved`로 기록한다. 승인 전에는 본 계산으로 이동하지 않는다.

### 4. 자동 기준안을 계산한다

공식 데이터와 재현 가능한 계산으로 기준안을 먼저 만든다. 계산에는 코드나 스프레드시트를 사용하고 원천 값, 변환, 산식, 단위 및 반올림을 추적한다.

다음을 구분해 기록한다.

- 관측 사실과 원천 데이터
- 원천 데이터에서 계산한 값
- 사용자 제공 가정
- 분석가 가정
- 해석과 판단

가정을 사용자에게 묻기 전에 합리적인 자동 기준안과 그 근거를 제시한다.

### 5. material 불확실성을 해결한다

[interaction-and-gates.md](references/interaction-and-gates.md)의 상태와 검토 라운드를 사용한다. 한 라운드에 서로 관련된 material 의사결정을 최대 3개까지 묶는다. 각 결정에는 실제로 구별되는 대안만 제시하고 추천안과 영향을 설명한다.

다음 항목은 material일 때만 질문한다.

- 방법론 또는 교차검증의 변경
- 낮은 신뢰도의 데이터나 대체 데이터 사용
- 성장, 마진, 투자, 자본비용 또는 정상화 가정
- 결과 표현 방식
- 결과를 유의하게 바꾸는 계산 처리

사용자 선택 후 기준안을 다시 계산하고 변경의 이유와 영향을 기록한다. 필요한 데이터가 확보되거나 부재가 공개되고, 모든 material 불확실성이 결정되면 반복을 끝낸다.

### 6. 검증하고 Gate 2 승인을 받는다

[validation.md](references/validation.md)를 읽고 모든 적용 항목을 확인한다. 오류나 설명되지 않은 불일치가 남아 있으면 Gate 2로 이동하지 않는다.

결과 특성에 맞춰 다음 중 가능한 표현을 추천한다.

- 단일 기준가치
- 기준가치와 민감도 범위
- Downside, Base, Upside 시나리오

[interaction-and-gates.md](references/interaction-and-gates.md)의 Gate 2 형식으로 데이터, 계산, 가정, 변경, 경고, 결과 형식 및 예정 보고서 구조를 요약한다. 사용자가 명시적으로 생성 승인한 경우에만 최종 보고서를 만든다.

### 7. 최종 보고서를 생성한다

[report.md](references/report.md)를 읽고 Gate 2에서 승인된 내용만 사용한다. 핵심 결론을 먼저 제시하고, 모든 핵심 수치가 근거와 계산으로 역추적되게 한다.

최종 보고서에서 새로운 가정, 데이터 대체, 방법론 변경 또는 경고 삭제가 필요해지면 생성을 멈추고 Gate 2로 돌아간다.

## 이 앱에서의 도구 매핑

이 절차는 The Associate 안에서 실행된다. 계산은 코드(engines)가 하고 값은 provider 가 뽑는다.
직접 산술하지 말고 아래 도구를 쓴다. 도구가 실패한 항목만 사용자에게 확인한다.

| 절차 단계 | 사용할 도구 |
|---|---|
| 2. 증거 가용성 | `get_financial_history`(최근 N개년 — 연도를 찍지 않는다), `get_financial_item`(+`_us`/`_jp`/`_tw`), `get_market_cap`, `search_dart_filings`/`read_dart_filing`, `get_figi` |
| 3. 적용 판단 | `get_business_mix` — 단일 FCFF DCF 적용 가능 여부(industrial / mixed / financial) |
| 4. 자동 기준안 (DCF) | `get_dcf_assumptions`(성장·마진·D&A·CAPEX·ΔNWC 5개년), `get_net_debt`, `compute_wacc_auto`, `get_terminal_growth` |
| 4. 자동 기준안 (Comps) | `compute_comps`(크로스보더·EV배수·LTM·공통 거래일을 엔진이 처리), 개별 확인은 `get_market_cap`·`get_ebitda`·`get_net_debt` |
| 4. 자본비용 세부 | `get_beta`(R²<0.3이면 산업베타로 전환), `get_market_cost_of_debt`(WACC용 시장 Kd), `get_cost_of_debt`(실효 Kd·교차검증), `get_industry_benchmarks` |
| 4. 본계산 | `compute_dcf`, `compute_comps`, `evaluate_sangjeung_value` |
| 6. 검증 | `compute_dcf`·`compute_comps` 결과 note 의 `⚠️` 경고를 반드시 확인해 보고서에 옮긴다 |

주의:
- 이 앱에는 코드 실행·스프레드시트가 없다. 산식 재현은 engine 이 돌려주는 note 와 extras
  (연도별 내역, EV/지분가치 bridge)를 인용해서 보인다.
- 연도 인자(`year`)는 **생략이 기본**이다 — provider 가 공시가 존재하는 최신 사업연도를 찾는다.
  오늘 날짜에서 연도를 역산해 넣지 않는다. 다년치가 필요하면 `get_financial_history` 를 쓴다.
- `get_dcf_assumptions` 는 **과거 5개년 평균**이다. 절차서가 금지하는 "과거 평균의 자동 채택"에
  해당하므로, 그대로 쓰지 말고 정상화가 필요한지 판단해 Gate 1 또는 검토 라운드에서 다룬다.
- 해외 기업의 자본비용(`compute_wacc_auto`·`get_beta`)에는 `country`·`market`·`symbol`·
  `industry` 를 함께 넘긴다(DART 는 한국 전용). 반면 시가총액·재무·순부채·EBITDA·comps 는
  `market` 코드만 주면 되고 종목코드·Yahoo 티커는 엔진이 유도한다.
- 크로스보더 비교표는 `compute_comps` 하나로 만든다. 항목마다 `'MU:US'` 처럼 시장을 붙이고,
  비교표 자체가 산출물이면 `target` 은 비운다. 기준일·기준기간·통화 정렬과 기준 불일치
  경고는 엔진이 만들어 주며, 그 경고를 보고서에 그대로 옮기는 것이 검증의 일부다.
- 최종 보고서는 대화 답변으로 작성한다. 파일은 사용자가 답변 아래 버튼으로 내려받는다 —
  **📄 HTML 리포트**(질문·답변·출처 전체) 및 계산한 방법에 대응하는 엑셀(**DCF 전체 모델
  5시트 / DCF 요약 / Comps / 상증법**). 엑셀은 입력이 파란 셀, 계산이 수식이고 '출처' 시트가
  붙어 있어 사용자가 가정을 바꿔 재계산할 수 있다. 보고서를 낼 때 어떤 파일을 받을 수 있는지
  한 줄로 알려준다.

## 완료 기준

다음 조건을 모두 충족해야 완료다.

- 평가 대상, 범위, 기준일, 통화 및 회계 기준이 명확하다.
- Gate 1과 Gate 2의 명시적 승인이 기록됐다.
- 모든 핵심 수치에 원천, 기준일, 단위 및 변환 경로가 있다.
- 적용한 방법의 검증 항목이 모두 통과했거나 남은 한계가 공개됐다.
- material 가정, 변경 및 데이터 한계가 보고서에 반영됐다.
- 승인 범위를 벗어난 입력이나 결론이 없다.
- 결과가 사용자의 선택 형식으로 제시됐다.
